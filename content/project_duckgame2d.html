Duckgame 2D is a small top-down bullet hell. The team consists of 2 programmers (myself included) with both handling all aspects of the game’s systems and features. We occasionally have 2 external artists create art assets as needed.

A key focus of the project has been designing modular, reusable systems that can be leveraged in larger or alternative Unity projects.

Showcase

Key Contributions

To manage core systems like audio, object pooling, and player input, I built a central Service Locator. Each system was implemented as a self-contained service, easily accessible from anywhere in the game without needing manual setup or scene references. These services are in only instantiated when first used, they persist across scenes, ensuring they're accessibe throughout the game. This approach allowed us to keep our core systems modular.

I built a service based on Unity's Input System to handle player controls modularly. It sets up a PlayerInput component at runtime and exposes simple methods for hooking into input events by name. The goal was to keep input handling clean, intuitive and modular.

I implemented a pooling system to imporve performance by reducing instantiation overhead. The service lets you register an object as a template for pooled instances, with optional variants and an initial pool size. It supports delayed releases and offers intuitive methods for fetching and recycling objects.

Object Pooling being used for Projectiles

A simple service I created to manage in-game audio, including background music and sound effects. It sets up audio sources for both OST and UI sounds and provides methods to play sound effects at specific locations or globally. Additionally, it allows volume control via Unity Audio Mixers and uses object pooling for sound effects to improve performance.

I contributed to the implementation of Entity2D as a base class for game objects with health, hitboxes, and movement. It includes methods for modifying health, handling invulnerability, and applying visual effects like flashing. Additionally, I implemented warnings that ensure essential components (collider, hitbox, rigidbody, and model) are properly set up and ready at runtime.

The Character2D class extends Entity2D to represent controllable players or agents (AI) with dashing and combat abilities. I primarily contributed by adding functionality to control character movement and orientation, ensuring characters look and move in the desired direction. I also introduced debugging features to visualise these behaviors, aiding development.
